# Онбординг: робота з сайтом breakoutmusic.io

Цей файл — для нового учасника команди. Пройди кроки згори вниз один раз, далі працюй за розділом «Щоденний цикл».

## Що потрібно мати

1. **Акаунт GitHub** — надішли Яні свій нікнейм, вона додасть тебе в репозиторій `artistpush-pr/artist-push-website` з правом Write.
2. **Акаунт Cloudflare** — надішли Яні email, вона надішле інвайт в акаунт (роль Administrator). Прийми лист-запрошення.
3. **Node.js** на компʼютері — перевір командою `node -v`. Якщо команди немає, постав з nodejs.org (LTS-версія).

## Разова настройка (15 хвилин)

**1. Забрати код**

```bash
git clone https://github.com/artistpush-pr/artist-push-website.git
```

Папка зʼявиться там, де ти запустила команду. Далі всі команди виконуй усередині неї:

```bash
cd artist-push-website
```

**2. Підключити Cloudflare**

```bash
npx wrangler login
```

Відкриється браузер → натисни **Allow**. Це один раз; далі термінал памʼятає доступ.

Перевірка, що все підхопилось:

```bash
npx wrangler whoami
```

Має показати email акаунта і назву акаунта Cloudflare.

## Структура: що редагувати

| Шлях | Що це | Редагувати? |
|---|---|---|
| **`live-snapshot/`** | ✅ **робочий сайт** — саме ця папка їде на breakoutmusic.io | **ТАК, тільки тут** |
| `breakout-api/` | бекенд: платежі, замовлення, промокоди, адмінка | тільки за погодженням з Яною |
| `*.html`, `*.js` у корені | ❌ стара копія (червень 2026), лишилась для історії | **НІ** — зміни сюди не потраплять на сайт |
| `website-upload/` | ❌ теж стара копія | **НІ** |

Це найчастіша пастка: у корені лежать файли з такими самими назвами, як у `live-snapshot/`. Якщо відредагувати кореневий `index.html`, на сайті нічого не зміниться.

## Щоденний цикл

**1. Перед початком роботи — забрати свіже:**

```bash
git pull
```

**2. Внести зміни** — тільки у файлах всередині `live-snapshot/`.

**3. Подивитись, що змінилось:**

```bash
git status
```

**4. Зберегти й відправити:**

```bash
git add -A && git commit -m "коротко що зробила"
```

```bash
git pull --rebase && git push
```

Коміти роби дрібні й пуш часто — так майже не буває конфліктів.

**5. Викласти на сайт:**

```bash
git pull
```

```bash
npx wrangler pages deploy live-snapshot --project-name=breakout-music-io --branch=main
```

Зміни зʼявляться на breakoutmusic.io протягом хвилини.

## Правила, які не можна порушувати

1. **`git pull` перед кожним деплоєм.** Деплой заливає на сайт **весь вміст твоєї локальної папки**. Якщо деплоїти зі старої копії — чужі зміни, які вже на сайті, зникнуть. Це єдина дія, якою реально можна зашкодити.
2. **Ніколи не роби `git push --force`** — це стирає чужу історію.
3. **Ніяких ключів і паролів у коді.** API-ключі живуть у секретах Cloudflare Worker, у репозиторії їх бути не може.
4. **Бекенд (`breakout-api/`) не чіпаємо без погодження** — там платежі, замовлення й база.

## Кеш: чому зміну не видно одразу

- Сторінки кешуються до **1 години**, файли в `assets/` — **на рік**.
- Якщо міняєш JS або CSS — зміни номер версії в підключенні: `script.js?v=2` → `?v=3`.
- Якщо міняєш картинку в `assets/` — заливай під **новим імʼям**, стара назва віддаватиме стару картинку.
- Щоб перевірити свою зміну в браузері — жорсткий рефреш: **Cmd+Shift+R** (Mac) або **Ctrl+F5** (Windows).

## Якщо щось пішло не так

**Конфлікт при `git pull --rebase`** — git покаже, у якому файлі. Відкрий файл, знайди блоки `<<<<<<<` / `=======` / `>>>>>>>`, залиш потрібний варіант, прибери маркери, тоді:

```bash
git add -A && git rebase --continue
```

**Задеплоїла не те** — зміни не втрачені: зроби `git pull`, переконайся, що локальна папка збігається з main, і задеплой ще раз.

**Не впевнена перед деплоєм** — краще напиши Яні, ніж деплоїти навмання.
